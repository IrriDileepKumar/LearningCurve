I.

Turning Text Into Numbers

Models don't read text. They need numbers. A tokenizer is the bridge: it splits text into small chunks (tokens), then maps each chunk to an integer ID from a fixed vocabulary.

In simpleTokenizer.py, we built a tiny hand-crafted vocabulary:

My llm/chapter2/encoders/simpleTokenizer.py # vocabulary mapping vocabulary = {'<pad>':0, '<unk>':1, '<s>':2, '</s>':3, 'hello':4, ',':5, 'how':6, 'are':7, 'you':8, '?':9, 'i':10, 'am':11, 'fine':12, 'thank':13, '.':15, 'goodbye':16, '!':17}

encode turns text into IDs. decode turns IDs back to text. Words not in the vocabulary become <unk> (ID 1).

Worked example

Input: "yo, how are you?" Tokens: ["yo", ",", "how", "are", "you", "?"] IDs: [ 1, 5, 6, 7, 8, 9 ] ^unk (not in vocab)

In bytepair.py, we switched to the real GPT-2 BPE tokenizer via tiktoken. BPE splits words into subwords, so rare words are broken into pieces while common words stay whole. GPT-2 has 50,257 tokens total.

II.

Sliding Windows for Training

A model cannot train on a big text file directly. It needs small batches of numbers with input/target pairs. The target is always the input shifted by one — predict the next token.

My llm/chapter2/encoders/data_preparation.py token_ids = tokenizer.encode(text) for i in range(0, len(token_ids) - max_length, stride): input_ids.append(token_ids[i : i + max_length]) output_ids.append(token_ids[i+1 : i + max_length + 1])

Worked example

token_ids = [A, B, C, D, E, F, G, H] max_length = 4, stride = 4 (non-overlapping) i=0 input: [A, B, C, D] target: [B, C, D, E] i=4 input: [E, F, G, H] target: [F, G, H, ?] The model learns: Given A -> predict B Given A,B -> predict C ...
Sliding Window — adjust max_length and stride
Blue = input window, green = target window (shifted by 1). Overlap shown when stride < max_length.

Finally, PyTorch's DataLoader groups many windows into batches. With batch_size=8 and max_length=4, each batch is a tensor of shape [8, 4] — 8 sequences of 4 tokens each.

III.

Token + Positional Embeddings

Token IDs are just arbitrary numbers. nn.Embedding turns each ID into a dense vector by looking up a row in a big weight matrix.

My llm/chapter2/encoders/TokenEmbedding.py vocab_size = 50257 # GPT-2 tokenizer size output_dim = 256 # embedding vector length token_embedding_layer = nn.Embedding(vocab_size, output_dim) # Internal weight matrix shape: [50257, 256]

How the lookup works

Embedding table E (50257 rows x 256 cols) Token ID 40 -> E[40] = [0.12, -0.05, 0.33, ..., 0.08] (256 numbers) Token ID 367 -> E[367] = [0.55, 0.87, 0.66, ..., -0.21] (256 numbers)

Positional embedding

Attention is order-agnostic — "cat ate fish" and "fish ate cat" would produce the same scores without position info. A second embedding table P encodes where each token sits:

Position table P (context_length x 256) final_vector = E[token_id] + P[position] Position 0: E[40] + P[0] Position 1: E[367] + P[1] Position 2: E[2885] + P[2] Position 3: E[1464] + P[3]

Each row is one token's vector. The model learns these values during training.

IV.

The "Journey" Example

Attention lets each word look at every other word and decide how much to listen. In this simplified version, Q = K = V = the input embeddings themselves (no learned projections yet).

My llm/Chapter 3 - Self Attention/simpleAttention.py input_embedding = torch.tensor([ [0.43, 0.15, 0.89], # Your (x1) [0.55, 0.87, 0.66], # journey (x2) <- query [0.57, 0.85, 0.64], # starts (x3) [0.22, 0.58, 0.33], # with (x4) [0.77, 0.25, 0.10], # one (x5) [0.05, 0.80, 0.55] # step (x6) ])

Step 1 — Attention scores (dot products)

For query = "journey" = [0.55, 0.87, 0.66], compute the dot product with every word:

score(journey, Your) = 0.55*0.43 + 0.87*0.15 + 0.66*0.89 = 0.9544 score(journey, journey)= 0.55*0.55 + 0.87*0.87 + 0.66*0.66 = 1.4950 score(journey, starts) = 0.55*0.57 + 0.87*0.85 + 0.66*0.64 = 1.4754 score(journey, with) = 0.55*0.22 + 0.87*0.58 + 0.66*0.33 = 0.8434 score(journey, one) = 0.55*0.77 + 0.87*0.25 + 0.66*0.10 = 0.7070 score(journey, step) = 0.55*0.05 + 0.87*0.80 + 0.66*0.55 = 1.0865

Step 2 — Normalize to weights (sum to 1)

sum = 0.9544 + 1.4950 + 1.4754 + 0.8434 + 0.7070 + 1.0865 = 6.5617 weights = [0.9544/6.56, 1.4950/6.56, ...] = [0.1455, 0.2278, 0.2249, 0.1285, 0.1077, 0.1656]

Step 3 — Context vector (weighted sum)

context = 0.1455 * [0.43, 0.15, 0.89] (Your) + 0.2278 * [0.55, 0.87, 0.66] (journey) + 0.2249 * [0.57, 0.85, 0.64] (starts) + 0.1285 * [0.22, 0.58, 0.33] (with) + 0.1077 * [0.77, 0.25, 0.10] (one) + 0.1656 * [0.05, 0.80, 0.55] (step) First number by hand: 0.1455*0.43 + 0.2278*0.55 + 0.2249*0.57 + 0.1285*0.22 + 0.1077*0.77 + 0.1656*0.05 = 0.0626 + 0.1253 + 0.1282 + 0.0283 + 0.0829 + 0.0083 = 0.4355 context vector = [0.4355, 0.6451, 0.5680]
Attention Calculator — click a word to use as query
Scores, weights, and the final context vector update when you pick a different query word.

For all words at once, the same idea becomes a matrix multiply:

full_attention_scores = X @ XT # QK^T (Q=K=X) full_attention_weights = softmax(scores) # normalize full_context_vector = weights @ X # weighted sum (V=X)
V.

Wq, Wk, Wv

In simplified attention, Q = K = V (same matrix). Real transformers give each a separate learned projection so the model can learn different views for querying, being queried, and carrying information.

My llm/Chapter 3 - Self Attention/trainableAttention.py w_q = nn.Parameter(torch.rand(d_in, d_out)) w_k = nn.Parameter(torch.rand(d_in, d_out)) w_v = nn.Parameter(torch.rand(d_in, d_out)) Q = X @ W_q # what am I looking for? K = X @ W_k # what do I contain? V = X @ W_v # what information do I carry?

The full formula

Q K^T Attention(Q, K, V) = softmax( --------- ) * V sqrt(d_k) Step 1: Q = X @ W_q shape (N, d_k) Step 2: K = X @ W_k shape (N, d_k) Step 3: V = X @ W_v shape (N, d_v) Step 4: Scores = Q @ K^T shape (N, N) Step 5: Scaled = Scores / sqrt(d_k) Step 6: Weights = softmax(Scaled) Step 7: Context = Weights @ V shape (N, d_v)
Q, K, V Projection Flow
Three separate weight matrices produce Q, K, V from the same input X.
Why sqrt(d_k)? Without scaling, dot products grow large in high dimensions, making softmax produce extreme values (nearly all 0s and one 1). Dividing by sqrt(d_k) keeps gradients well-behaved during training.
VI.

No Peeking Forward

In GPT, when predicting the next token at position 3, the model must not see tokens at positions 4, 5, 6... That would be cheating. Causal attention masks the upper triangle of the score matrix with -inf so future tokens get zero weight after softmax.

My llm/Chapter 3 - Self Attention/casualAttention.py casual_mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1).bool() scaled_attention_scores.masked_fill_(casual_mask, float('-inf')) attention_weights = torch.softmax(scaled_attention_scores, dim=-1)

Worked example (6 words)

Causal Mask — toggle to see the effect
With the mask ON, each word can only attend to itself and earlier words. -inf becomes 0.00 after softmax.
VII.

Parallel Views

One attention pass captures one kind of relationship. Multi-head attention runs several attention passes in parallel, each on a slice of the embedding, then concatenates the results.

My llm/Chapter 4 - LLM Architecture/multiHeadAttention.py self.num_heads = num_heads # 12 self.head_dim = dimension_in // num_heads # 768/12 = 64 query = self.w_query(inputs).view(B, N, num_heads, head_dim) key = self.w_key(inputs).view(B, N, num_heads, head_dim) value = self.w_value(inputs).view(B, N, num_heads, head_dim)

The split

Multi-Head Split — 768 dims into 12 heads of 64
Each colored chunk is one attention head. Every head runs its own Q, K, V attention independently.
embedding_dim = 768 n_heads = 12 head_dim = 768 / 12 = 64 Each head: Q_h, K_h, V_h are [N, 64] slices scores_h = Q_h @ K_h^T / sqrt(64) [N, N] context_h = softmax(scores_h) @ V_h [N, 64] After all 12 heads: concat -> [N, 768] -> output linear
Analogy: 12 experts read the sentence at the same time. One might focus on grammar, another on nearby words, another on meaning links. Then their 12 reports are merged.
VIII.

Private Thinking

After attention (where tokens share info), each token goes through a feed-forward network privately — no interaction with other tokens.

chapters/Chapter 4 - LLM Architecture/feedForward.py class FeedForward(nn.Module): def __init__(self, config): self.layers = nn.Sequential( nn.Linear(config["embedding_dim"], 4 * config["embedding_dim"]), nn.GELU(), nn.Linear(4 * config["embedding_dim"], config["embedding_dim"]) )
FFN shape flow: 768 --> 3072 --> GELU --> 768 (expand 4x) (activate) (compress back)

LayerNorm

Layer Normalization keeps activations stable by normalizing each token vector to have zero mean and unit variance, then applying a learned scale and shift.

LayerNorm(x) = scale * (x - mean) / sqrt(variance + eps) + shift For a token vector x = [a, b, c, ..., 768 values]: mean = average of all 768 values variance = spread of all 768 values eps = 1e-5 (avoids division by zero)

Skip connections (residuals)

Each sub-block adds its original input back to the output. This means the model only needs to learn small refinements rather than reconstructing everything from scratch.

x --> LayerNorm --> Attention --> Dropout --> + x (residual) --> LayerNorm --> FFN --> Dropout --> + x (residual)

X.

Predicting the Next Token

The final layer is a simple nn.Linear(768, 50257). It multiplies each token's 768-dim hidden vector by a weight matrix to produce one score per vocabulary token. The highest score wins.

Worked example (tiny: 4 dims, 5 tokens)

Hidden vector h = [0.5, -0.2, 0.8, 0.1] (4 numbers) Weight matrix W (5 x 4): row 0: [ 0.1, 0.2, -0.1, 0.3] -> token "the" row 1: [ 0.4, -0.3, 0.2, 0.1] -> token "cat" row 2: [-0.2, 0.5, 0.3, -0.4] -> token "sat" row 3: [ 0.3, 0.1, 0.0, 0.2] -> token "on" row 4: [ 0.2, 0.4, -0.3, 0.5] -> token "it" Score for "the" = h . row0 = 0.5*0.1 + (-0.2)*0.2 + 0.8*(-0.1) + 0.1*0.3 = 0.05 - 0.04 - 0.08 + 0.03 = -0.04 All scores: "the" = -0.04 "cat" = 0.42 "sat" = 0.10 "on" = 0.19 "it" = 0.11 argmax -> "cat" (score 0.42) <- predicted next token
Output Scores — bar chart of next-token prediction
Each bar is a dot-product score. The tallest bar (green) is the model's prediction for the next token.

In the real BeensGPT, the hidden vector has 768 numbers and there are 50,257 possible tokens. Same math — just a much bigger matrix multiply.

Interesting symmetry: The embedding layer maps token ID -> 768-dim vector (lookup row k). The output layer maps 768-dim vector -> score per token (dot product with row k). They are reverse directions of the same idea.

Token numbers in → model thinks → scores for all token numbers → pick best one.
