Speculative Decoding

How a small model's guesses let a big model verify in bulk — for 2–3× faster inference with identical outputs.

Based on Fast Inference from Transformers via Speculative Decoding by Leviathan, Kalman & Matias (Google Research, ICML 2023 Oral). Instead of generating one token at a time, let a cheap draft model guess several tokens ahead, then have the expensive target model verify them all in one forward pass.

I.

Why Autoregressive Decoding is Slow

Traditional autoregressive decoding generates one token per forward pass. For K tokens, the large model executes K sequential forward passes. Each pass loads billions of parameters from memory, and most of the GPU's arithmetic units sit idle.

Prompt ↓ Large Model → Token1 (50 ms) Large Model → Token2 (50 ms) Large Model → Token3 (50 ms) Large Model → Token4 (50 ms) Total: 200 ms for 4 tokens

The key insight: the large model can evaluate multiple positions simultaneously in a single forward pass (just like during training). Speculative decoding exploits this by filling those positions with educated guesses.

II.

Draft, Verify, Accept

The system uses two models:

Small Draft Model (fast, approximate) ↓ Predicts γ future tokens cheaply ↓ Large Target Model (slow, accurate) ↓ Verifies all γ predictions in one forward pass ↓ Accept correct guesses, fix incorrect ones

If the draft model predicts correctly, multiple tokens are generated for the cost of a single large-model forward pass.

Worked example

Prompt: "Once upon a" Draft model predicts: time there was a Target model verifies all 4 in one pass: time ✓ (accept) there ✓ (accept) was ✓ (accept) a ✓ (accept) Result: 4 tokens generated in 1 expensive pass Normal decoding: 4 tokens in 4 expensive passes

III.

The Algorithm — Step by Step

Step 1: Draft generation. The small model generates γ tokens autoregressively, recording each token's probability q(x).

Prompt: "The capital of France is" Draft model (e.g. Llama 8B) predicts γ=5 tokens: Paris and it is famous Each with draft probabilities q(x): q(Paris)=0.80 q(and)=0.60 q(it)=0.55 q(is)=0.50 q(famous)=0.40

Step 2: Parallel verification. The target model computes probabilities for all γ drafted positions in a single forward pass.

Target model (e.g. Llama 70B) evaluates all 5 positions at once: p(Paris | ...France is) = 0.70 p(and | ...France is Paris) = 0.45 p(it | ...Paris and) = 0.50 p(is | ...and it) = 0.55 p(famous | ...it is) = 0.35

Step 3: Accept or reject. Each token is accepted with probability min(1, p(x)/q(x)). The first rejected token and everything after it are discarded. A corrected token is sampled from the residual distribution.

IV.

Why Outputs are Identical

This is the paper's main contribution. It's not just "small model guesses, big model checks." The authors prove that the output distribution is exactly identical to sampling from the target model alone.

The trick is modified rejection sampling. Each drafted token x is accepted with probability:

acceptance probability = min(1, p(x) / q(x)) where p(x) = target model probability q(x) = draft model probability

Why naive acceptance would be wrong

If we simply accepted every draft token, the output distribution would match the draft model, not the target. Consider:

Target distribution p(x): Draft distribution q(x): Paris : 0.70 Paris : 0.80 London : 0.20 London : 0.10 Rome : 0.10 Rome : 0.10 Naive acceptance → output follows q(x), not p(x) Rejection sampling → output follows p(x) exactly
Interactive — Acceptance Probability
When p(x) ≥ q(x), the token is always accepted. When q(x) overestimates, acceptance probability drops proportionally.

Acceptance for each token

Token p(x) q(x) min(1, p/q) Accepted? Paris 0.70 0.80 0.875 87.5% of the time London 0.20 0.10 1.000 Always accepted Rome 0.10 0.10 1.000 Always accepted

When the draft model underestimates a token's probability (p > q), that token is always accepted. Rejection only happens when the draft model is overconfident relative to the target.

V.

What Happens on Rejection

When a token is rejected, the algorithm does not simply pick the highest-probability remaining token. Instead, it samples from the residual distribution:

residual(x) = max(p(x) - q(x), 0) Then normalize so probabilities sum to 1.

Worked example

Target p(x): Paris=0.70 London=0.20 Rome=0.10 Draft q(x): Paris=0.90 London=0.05 Rome=0.05 Residual (before normalizing): Paris : max(0.70 - 0.90, 0) = 0.00 London : max(0.20 - 0.05, 0) = 0.15 Rome : max(0.10 - 0.05, 0) = 0.05 Normalize (sum = 0.20): Paris : 0.00 London : 0.15/0.20 = 0.75 Rome : 0.05/0.20 = 0.25 Sample from: London (75%) or Rome (25%)

This is what preserves the exact target distribution. The rejected token was overrepresented by the draft model, so the residual compensates by boosting the tokens the draft model underrepresented.

VI.

How Many Tokens to Draft

The draft length γ controls the trade-off between speculation cost and verification payoff:

γ = 1 → Almost no speedup (just one guess) γ = 5 → Good balance for most model pairs γ = 50 → Many predictions get rejected, wasting draft compute

There's an optimal γ that depends on the acceptance rate α and the relative cost of draft vs. target model. If the draft model is much cheaper than the target, larger γ values are worth trying. If the acceptance rate is low (draft model is poor), smaller γ avoids wasted work.

Intuition Think of autocomplete on your phone. If it suggests "Thank you very much" and that's what you intend, you accept the whole phrase instantly. If it suggests "Thank you very elephant," you accept "Thank you very" and type the rest yourself. You still save time because most predictions are correct.
VII.

The Math Behind the Speedup

Define α as the probability that a single drafted token is accepted. The expected number of accepted tokens from a draft of length γ is:

Expected accepted = 1 + α + α² + α³ + ... + αˆγ For α = 0.9, γ = 4: 1 + 0.9 + 0.81 + 0.729 + 0.6561 = 4.10 tokens So one target-model forward pass produces ~4 tokens on average.

Guaranteed progress: even in the worst case (first draft token rejected), the algorithm still samples one corrected token from the target model. Every target-model pass produces at least one token. It never gets stuck.

When speculative decoding is slower

Draft: A B C D (cost: 4 × draft_time) Verify: A ✗ (cost: 1 × target_time) Then regenerate: A' B' C' D' (cost: 4 × target_time) Total = 4·draft + 5·target = 5 expensive passes + draft overhead Normal = 4 expensive passes If first token is always wrong, speculative decoding is slower.

This is why choosing a good draft model matters. With a well-matched pair (e.g. Llama 70B + Llama 8B), the acceptance rate is high enough that the typical case is several accepted tokens per verification pass.

VIII.

Memory vs. Compute

Large Transformers at inference time are typically memory-bandwidth bound, not compute-bound. Loading billions of parameters from HBM dominates latency, while the GPU's arithmetic units are underutilized.

Verifying γ positions instead of 1 uses roughly the same memory bandwidth (the model weights are loaded once either way) but fills more arithmetic slots. Speculative decoding essentially uses otherwise idle compute for free.

Single-token decode: Load 70B params from HBM → ~40 ms (memory-bound) Compute 1 token → ~2 ms (mostly idle) Total: ~42 ms for 1 token Speculative verification (5 tokens): Load 70B params from HBM → ~40 ms (same cost) Compute 5 tokens → ~8 ms (uses idle ALUs) Total: ~48 ms for 5 tokens → ~5× throughput

X.

Impact & Variants

This paper introduced one of the most influential LLM inference optimizations. Many modern serving systems now use speculative decoding or its descendants:

VariantKey Idea
Assisted GenerationHuggingFace integration of basic speculative decoding
MedusaMultiple prediction heads instead of a separate draft model
EAGLEFeature-level autoregression for draft generation
SpecInferTree-based speculation with multiple draft sequences
Multi-draftRun several draft models in parallel for higher acceptance
Key takeaway Speculative decoding is purely an inference algorithm. It does not train a new model, modify Transformer layers, change attention, or fine-tune anything. It works with any existing pretrained model pair where the small model is a reasonable approximation of the large one.

To master this paper

Study these four ideas in order: (1) Transformer autoregressive generation and why it's sequential, (2) the draft-and-verify intuition, (3) modified rejection sampling and why the output distribution is unchanged, and (4) expected speedup analysis using α and γ. With those four pieces, you also have the foundation for understanding Medusa, EAGLE, and SpecInfer.
